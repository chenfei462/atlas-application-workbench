# 公开硕士申请文书与学生经验：写法研究

研究日期：2026-10-13（Asia/Tokyo）。范围：为 Atlas 个人自用的香港／新加坡授课型硕士文书工作台提炼写作方法。本文件为研究记录，不是用户文书，也没有改变代码或数据库。

结论：可以学习公开案例如何把“经历—问题—学习目标—项目资源”接起来，不能移植案例作者的经历、课程、成绩、成果或职业目标。查到学校注明授权公开的硕士申请原文，也查到作者本人公开全文并自述录取的硕士案例；本轮没有找到由学校独立确认录取结果、同时公开完整原文的香港／新加坡金融、CS 或数据授课型硕士案例。不能据此证明某种文书写法单独促成录取。

## 证据分级

| 层级 | 用途 | 限制 |
|---|---|---|
| 官方招生要求 | 约束目标项目的题目、篇幅、材料与原创性要求 | 仅适用于对应学校、项目及申请季，项目专属要求优先 |
| 学校官方学生博客 | 学习在读学生实际准备与修订方法 | 作者经验不是招生委员会统一规则 |
| 学校授权公开样例 | 观察真实申请文字如何组织论据 | 授权公开不等于确认录取，也不保证写法全部值得模仿 |
| 作者本人公开、录取自述 | 低权重观察完整叙事结构 | 自述结果缺乏独立核验；不能归因于文书 |
| 机构营销“成功案例” | 最多用于发现待核实线索 | 本轮未纳入依据；无作者授权、原文或结果来源不当作真实成功样本 |

## 适合 Atlas 的五个写作动作

下列为本研究的工具设计推论，不是学校公布的统一评分表。

| 写作动作 | 编辑时做什么 | 缺事实时先问什么 |
|---|---|---|
| 具体开头 | 用已确认的项目、课程或工作问题切入，并尽早点明申请方向；无需强行戏剧化 | 哪个实际任务使你开始考虑该领域？当时你的角色和遇到的问题是什么？ |
| 证据连着反思 | 每段有任务、个人行动、可核实结果／限制，以及学习判断；不给每个项目都硬加漂亮指标 | 你亲自做了哪一步？结果如何确认？什么没解决、为什么？ |
| CS／PM 转金融 | 把数据处理、建模、交付或跨团队决策能力接到一个具体金融问题，再说明要补的金融知识 | 你真实接触过什么金融问题？技术能力能处理哪一部分，哪一部分还缺经济或金融理解？ |
| 项目专属匹配 | 从核验过的目标项目资源选少量最相关项，写清“补什么—怎么学—用于什么” | 该模块／实践机会是否确实开放给这个学位、这个申请季？它如何解决你的能力缺口？ |
| 删除空泛判断 | 将排名、城市地位、“优秀分析能力”“热爱金融”等说法改成证据或具体目标 | 除去学校名称，这句话是否仍适用于任何项目？有什么事实能让它只属于你？ |

“证据连着反思”来自公开材料组织方式的综合观察。CS／PM 转金融是针对工具当前方向的推论，不能仅凭 CS 专业或项目经理头衔推断用户已经掌握金融分析。[官方金融示范](https://blogs.lse.ac.uk/careers/2021/05/25/writing-a-personal-statement-for-further-studies/)支持考察可迁移技能；最终金融适合度仍要由用户真实事实支撑。

## 原创短例：用于提问与方法演示，均非用户事实

以下 before／after 为本研究原创的教学文字，非任何学生原文；方括号是教学示意，不能自动替换成推测事实或作为完成稿输出。

**具体开头**

- Before：`I have always been passionate about finance and technology.`
- After（结构演示）：`In [confirmed task], I encountered [specific limitation]. It led me to ask [the applicant's actual question].`
- 下一步提问：请确认一个实际任务、你个人承担的动作和当时产生的问题；尚未确认，就先保留“待补事实”的编辑任务。

**把能力变成论据**

- Before：`My project management experience proves my excellent analytical ability.`
- After（结构演示）：`I was responsible for [confirmed responsibility]. After [confirmed action], I learned [the applicant's own reflection], while [remaining limitation] remained unresolved.`
- 下一步提问：职责有项目记录吗？哪些行动属于你而非团队？反思请用户本人表述；无指标就不编百分比、用户规模或增长结果。

**项目匹配**

- Before：`Your world-class university in a global financial centre is my ideal choice.`
- After（结构演示）：`[Verified programme resource] would help me develop [identified skill gap], which I need for [the applicant's confirmed next step].`
- 下一步提问：当前申请项目的官方页面有没有该资源？你为什么需要它？用户尚未确定职业方向时，不替其设定量化交易、投行或风险管理目标。

## 与当前实际字段对接的建议

已只读检查 `src/forms.ts`、`src/main.ts`、`src/essay-save.ts`，以下区分现有字段和建议补充信息，不声称已实现。

1. **用户事实用现有 `evidence_items`。** `title`、`organization`、`role`、日期、`description`、`responsibilities`、`achievements`、`metrics`、`skills`、`technologies` 各写事实；`verified` 仅是当前用户确认标记，不自动等同独立凭证。通过 `evidence_material_links` 接到材料。不要把模板种子或旧静态页面的经历当作用户事实。
2. **论点追溯到版本。** `essay_evidence_items` 记录文书选用经历；`essay_evidence_links.essay_version_id`、`evidence_item_id`、`claim_note` 用来说明该版本哪项主张由什么事实支撑。量化成果应能追到材料或用户明确的依据。
3. **项目事实另用现有来源体系。** `program_essay_requirements.prompt`、`word_limit`、`source_id` 约束该项目文书；`sources.url`、`verified_at` 与 `source_assertions` 保存课程／项目资源的核验。不把本文件的写作参考来源标成港新项目的官方要求。
4. **反思和未来目标需要用户回答。** 当前 `profiles` 编辑字段只有 `display_name` 与 `timezone`，不足以支持教育、成绩、动机或职业目标；建议事实收集引导明确询问“个人行动、结果依据、失败／限制、本人反思、转方向动机、能力缺口、拟用项目资源、职业下一步”。如果短期不扩展表结构，可按清晰标签存在相关事实 `notes`，并保留来源为用户输入。
5. **模板应生成问题和段落框架，不补个人事实。** 草稿可显式标记待补信息；不得静默填入姓名、院校、GPA、金融实习、论文、获奖等级、成果数字或虚构转专业契机。展示“方法示例”与用户正文的明确边界。标成可提交／完成之前，检查未补占位、事实来源、题目覆盖与篇幅，按目标项目规则确认原创性。

建议工作流：选具体项目与最新官方题目 → 选择真实事实 → 回答关键追问 → 决定主线与取舍 → 自己起草／修订 → 检查论据和要求 → 保存新版本及依据。这个流程优先改善事实质量与论证，不用“录取概率”或“招生官偏好分”包装未知判断。
